What two months of validation fixed in tools-iuc, and what we propose next.

Why the legacy path has to go

A test can declare a parameter, the legacy path drops it, the tool runs without it, and the test still passes.

stacks2 test declareslegacy path sendstyped path sends
--rm-pcr-duplicatesnothing--rm-pcr-duplicates
--bestradnothing--bestrad
capture=truedefaultcapture=true

That is a false green, which is worse than a red. The typed path refuses instead: could not build request: unhandled inputs. Every framework defect we found surfaced that way.

5

Async is already the default

  • galaxyproject/galaxy#23329 merged on 12 September. Tool requests are on by default for the browser form in the next release.
  • Across the full suite, 27 tests pass only under async against 12 that pass only under sync. Switching is net positive before counting the false greens.
  • The test client did not follow. DEFAULT_USE_LEGACY_API = "always" in galaxy-tool-util, and released planemo does not override it, so every planemo driven test in CI still submits to the legacy endpoint.

The default switched for users and not for the tests that guard it.

6

Proposal: move the ecosystem to async

  • Land the planemo flag. --use_async_submission exists on a branch and is eight lines. Released galaxy-tool-util already carries the capability, so nothing else is needed.
  • Switch tools-iuc CI. One line, additional-planemo-options, once the flag is in a release.
  • Extend to usegalaxy.eu. Their custom tool repositories are structured like tools-iuc, so the same scripts run against them unchanged. That team supports the move.
  • Then flip the default in galaxy-tool-util, so async is what a test exercises unless someone opts out.
7

How we work the backlog

  • Measure recurrence, not counts. A failure seen once is noise. Across four runs, 13 tests failed at least once and only 5 recurred.
  • Separate test debt from tool rot. Of 139 failures in the current baseline, roughly 70 are external services, 25 are drifted assertions, and a dozen are tools that no longer work at all. Only the middle group is ours to fix.
  • Refactor, do not widen. Assert what the output contains. A tolerance hides the next regression, and in one case hid a fixture generated from a different invocation.
  • Verify every fix against a run before claiming it.
